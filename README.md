# NewsEE: Event Information Extraction from News Text with Large Language Models

Code, data preparation and results for the MSc dissertation (School of Electrical and Electronic
Engineering, NTU, 2026). NewsEE extracts **entities, event triggers and event arguments** from
English news-style documents with a staged prompting framework on top of off-the-shelf LLM APIs.
No model is fine-tuned.

```
document ─► 1 entity recognition ─► 2 trigger detection ─► 3 argument labelling (one call per event type,
            (LLM call)               (LLM call)              each trigger given with its sentence)
                                                         ─► 4 grounding verification (rules, no LLM)
```

Each stage can be switched off for the ablation study: task decomposition, annotation guidelines,
retrieved demonstrations (TF-IDF nearest training documents, k = 3), and verification.

## Headline results (test set, 120 documents, F1)

| model | method | Trig-C | Arg-C (exact) |
|---|---|---|---|
| ds-flash (`deepseek-flash`) | zero-shot baseline → NewsEE | 32.3 → 57.5 | 15.6 → 26.0 |
| glm-4.7 (`glm-4.7`) | zero-shot baseline → NewsEE | 34.9 → 55.7 | 15.6 → 23.9 |
| ds-pro (`deepseek-v4-pro`) | zero-shot baseline → NewsEE | 25.5 → 47.2 | 12.7 → 22.7 |
| glm-air (`glm-4.5-air`) | zero-shot baseline → NewsEE | 16.5 → 38.8 | 6.9 → 17.6 |

Every improvement is significant (paired bootstrap over documents, 1000 samples, 95% CI excludes 0).
Given gold triggers, the framework reaches Arg-C 35.8–43.0, so trigger detection is the main bottleneck.
Three independent runs of ds-flash give a standard deviation of at most 0.6 F1 on every metric.
All tables are in [`results/`](results/README.md); `python scripts/verify_results.py` recomputes
every number from the saved model outputs.

## Repository layout

```

  guidelines.py         annotation guidelines injected into prompts (switchable)

  retrieval.py          TF-IDF demonstration retrieval (and the random-demo control)

  stats.py              paired bootstrap
  llm.py                OpenAI-compatible client with an on-disk reply cache
  runner.py             runs a method over a split and saves predictions, traces, metrics
  config.py             paths, sample sizes, model list, prices

                        metrics.json, run.json (configuration, calls, tokens)

results/                tables and figures used in the dissertation
.cache/                 every LLM reply, keyed by model + prompt + parameters
```

## Setup

Tested with Python 3.13 on macOS (Apple M1, 8 GB RAM); no GPU is needed because all models are called through APIs.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # add DEEPSEEK_API_KEY and ZHIPU_API_KEY (never share this file)
python scripts/check_api.py     # sends one tiny request per configured model
```

## Data

The experiments use **MAVEN-Arg** (Wang et al., ACL 2024), downloaded from
https://github.com/THU-KEG/MAVEN-Argument. The dataset is not redistributed here.
Place `train.jsonl` and `valid.jsonl` in `~/Downloads/MAVEN-Arg` (or set `MAVEN_DIR`), then:

```bash
python scripts/prepare_data.py
python scripts/evaluate.py --oracle --gold data/dev.jsonl   # scorer self-check: every metric must be 100
```

`prepare_data.py` keeps the 12 selected event types, skips documents over 600 words and, with seed 42,
draws 30 validation documents for development (`dev.jsonl`) and 120 for reporting (`test.jsonl`).
MAVEN-Arg's own test labels are hidden, so its validation split serves as our evaluation data.
Training documents of up to 400 words form the demonstration pool (`pool.jsonl`).

## Reproducing the experiments

Every LLM reply is stored in `.cache/`. With the cache in place, re-running any command below makes
**no API calls, costs nothing and gives exactly the reported numbers**. Without the cache the runs call
the APIs again; costs are DeepSeek off-peak list prices (Zhipu runs used prepaid resource packs).
`scripts/reproduce_all.sh` lists all commands in order.

| experiment | command | output | approx. cost without cache |
|---|---|---|---|
| Zero-shot baseline, dev | `run_baseline.py --model <m> --split dev` | `runs/baseline_zs_<m>_dev` | < 1 RMB |
| Ablation, dev (7 settings) | `run_ablation.py --model <m> --split dev` | `results/ablation_<m>_dev.md` | ds-flash about 3 RMB |
| Demonstration count k = 0/1/3/5 | `run_ablation.py --model glm-air --split dev --shots 0,1,3,5` | `results/shots_glm-air_dev.md` | resource pack |
| Main experiment, test | `run_main.py --model <m>` | `results/main_<m>_test.md` | ds-flash 3, ds-pro 17 RMB |
| Unseen event types | `run_unseen.py --model glm-air` | `results/unseen_glm-air_test.md` | resource pack |
| Thinking mode | `run_main.py --model ds-flash-think --skip-goldtrig` | `results/main_ds-flash-think_test.md` | about 13 RMB |
| Stability, 2 extra runs | `run_repeat.py --model ds-flash --runs 2` | `results/repeat_ds-flash_test.md` | about 5 RMB |
| Dictionary baseline (no LLM) | `run_lexicon.py --split test` then `compare_lexicon.py` | `results/lexicon_test.md` | none |
| Dictionary + LLM combination | `run_lexicon.py --split dev`, then `run_hybrid.py --split dev` and `--split test` | `results/hybrid_<split>.md` | none |
| Cross-model table | `summarize.py` | `results/summary_test.md` | none |
| Cost vs F1 figure | `cost_analysis.py` | `results/cost_test.md`, `fig_cost_vs_f1_test.png/.pdf` | none |

| Significance of any two runs | `significance.py --gold data/dev.jsonl --a runs/A --b runs/B` | printed | none |
| Check all reported numbers | `verify_results.py` | printed | none |

## Evaluation protocol

- The scorer was frozen before any reported run (`scorer.py`; self-check above gives 100 on gold).
- Entity-C: mention text and type. Trig-I / Trig-C: trigger text (and event type), as a multiset.
  Arg-I / Arg-C: arguments of a predicted event aligned to a gold event through its trigger (and type),
  coreferent mentions merged, one-to-one matching; reported as exact match and as bag-of-words F1,
  following the official MAVEN-Arg evaluation. Text is de-tokenised and SQuAD-normalised.
- All design choices were made on the 30 dev documents; the 120 test documents were run once per setting.
- Decoding: temperature 0, seed 42, JSON output mode, thinking disabled (except `ds-flash-think`).

## Notes on things that happened during the experiments

- **Entity guideline revision (dev only).** The first entity rules asked for all pronouns and hurt
  precision. After checking MAVEN-Arg training annotations (subject pronouns are annotated, possessives
  and dates almost never), one rule was added (`guidelines.py`, line 11). The pre-revision ablation is
  kept as `results/ablation_ds-flash_dev_guidelineV1.md`; it can be reproduced by removing that line.
- **Content filter.** Zhipu's safety filter occasionally refuses war or casualty news. Refused calls are
  recorded as empty replies and scored as "no output" (about 1% of calls; column *blocked* in the tables).
- **Rate limits.** `glm-4.7` is run with one request at a time (`config.MAX_WORKERS`).
- **Thinking mode.** With reasoning enabled, DeepSeek used its whole output budget (about 8k tokens per
  call) on reasoning in 89% of baseline calls and 40% of framework calls, leaving no answer.
- **Token accounting.** `run.json` records tokens of fresh calls; a cached re-run keeps the original
  numbers (`runner._usage_for_record`).
- **Human check of errors.** 98 framework errors (14 per error type) were pre-labelled by Claude and
  confirmed by the author one by one (`results/errors_ds-flash_test_sample_final.csv`). Because the
  suggestions were visible, this is a model-assisted check, not independent double annotation.
